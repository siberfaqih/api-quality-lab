## Finding (MEDIUM) — report verifier accepts synthetic report trees

The reviewer inspected `harness/report-check.ts` (lines 109–142, 194–239,
221–232) and found the report checks prove too little about *which* tests the
reports contain and *what* produced them:

1. `checkHtml` (lines 109–120) accepts any file containing `<!DOCTYPE html`
   and `<html` — a generic, non-Playwright page passes. It does not look for
   Playwright-specific markers.
2. `checkBaseline` (lines 122–143) checks only the JUnit counts (32 tests, 0
   failures/errors/skips). It never inspects testcase identities, so a report
   with 32 unrelated green testcases (e.g. `QA-FAKE-*`) passes.
3. `checkMutation` (lines 145–178) checks counts plus the presence of the
   expected failing QA ids. It never inventories the *other* testcases, so a
   mutation report with the right count and the right failing ids but wrong
   remaining testcases passes.
4. The self-test fixture (`writeFixtureTree`/`fixtureJUnit`, lines 194–232)
   builds its reports from synthetic `QA-OK-NN` names, encoding the same weak
   assumption the checker enforces.

Net effect, demonstrated by the reviewer with a synthetic probe: an unrelated
32-green-test tree with generic HTML, or a mutation tree with the expected
count and failing ids but otherwise unrelated contents, is **incorrectly
reported PASS**.

The review requires:

- HTML check: require Playwright-specific markers — the `<title>Playwright
  Test Report</title>` title and the `playwrightReportBase64` embedded-data
  marker — instead of the generic doctype/html substring.
- Baselines (`api-baseline`, `harness-eval/baseline-pre`, `harness-eval/
  baseline-post`): require the exact, unique QA testcase inventory of the real
  32-test suite, not just the count.
- Mutations: require the exact, unique QA testcase inventory of the targeted
  spec (validation 9, authz 2, isolation 2) in addition to the exact failing
  subset — no missing, extra, duplicated or substituted ids.
- Derive the expected inventories from the actual suite discovery/config
  (fail closed on drift), without weakening any existing assertion.
- Add negative controls: generic-HTML report rejected, unrelated all-green
  baseline (e.g. `QA-FAKE` ids) rejected, wrong mutation inventory rejected,
  duplicate ids rejected, plus the existing negatives kept green.
- Wording discipline: these are consistency/authenticity sanity checks, not
  cryptographic provenance. Do not claim markers prove origin.
