## Finding (MEDIUM) — broad assertion substrings accept HTTP 500

The mutation classifier accepted a failure when the expected QA id was present
and a broad assertion substring appeared in the error message, without proving
the expected/received semantics. In an independent synthetic probe, the
expected ids were present while a negative-price HTTP 500 response was accepted
(`accepted: true`, `errors: []`). The existing `CRASH_MARKERS` list is
insufficient to catch this.

Required semantics, mutation by mutation:

| QA id | Expected | Received |
| --- | --- | --- |
| QA-VAL-02 | 400 | 201 |
| QA-VAL-07 | >= 3 | 2 |
| QA-AUTHZ-02 | 401 | 200 |
| QA-ISO-01 | 404 | 200 |

The review requires:

- Reject HTTP 500 and any wrong received value for every expected failing QA
  id, not just a substring match.
- Add negative controls for HTTP 500 and for wrong received values for each
  expected failing QA id.
- Use structured evidence or robust exact semantic parsing, failing closed
  when the values are missing or ambiguous.
- The auth test may need a status assertion before the challenge-header
  assertion so a wrong 500 is distinguishable; strengthen the legitimate
  assertion, do not weaken it.
