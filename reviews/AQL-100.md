## Findings

### 1. MEDIUM — Name normalization and PATCH requirements contradict schema semantics

**Location:** `contract/openapi.yaml:577–582, 606–610, 808–835`; PATCH links at `325–328`.

**Impact:** Implementers and test authors cannot derive one consistent acceptance rule.

**Evidence:**
- REQ-VAL-01 permits names of 1–80 characters **after trimming**, but request schemas apply `maxLength: 80` to the incoming string.
- Independently tested `" " + "a".repeat(80) + " "`: trimmed length 80, raw length 82; AJV rejects it.
- PATCH links REQ-VAL-01/02/03, whose statements say name, price and quantity are required and missing values return 400. PATCH simultaneously promises supplied-fields-only updates and has no required fields.

**Remediation:** Specify normalization and validation order consistently with the request schema. Scope required-field/default rules explicitly to creation; on PATCH, validate only supplied fields and preserve omitted values.

### 2. MEDIUM — Validator accepts material contract weakening

**Location:** `harness/contract-rules.ts:410–479, 517–557, 610–685`; `PROGRESS.md:134–138`; `contract/README.md:50–54`.

**Impact:** Green validation does not establish the advertised boundary, error-response and success-shape protections.
